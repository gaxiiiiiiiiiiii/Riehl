## プロジェクトの目的

{{BOOK_AUTHOR}}, *{{BOOK_TITLE}}* を読むための個人的な Lean プロジェクトです。ユーザー自身が Lean で定義と定理を再現しながら読み進めることが目的で、対象範囲は {{SCOPE}} です。

エージェントの主な役割は、節ごとに演習ファイル（`.lean`）を用意すること、および Mathlib・Lean・数学概念についての質問に答えることです。

演習ファイルはテキストの副読本で、出典はテキストです。本文の定義と定理を、読者が Lean で自分の手で組むためのものです。作り方は `/exercises` にあります。

1節につき演習ファイルを1つ、章ごとのディレクトリ（`{{CHAPTER_DIR_EXAMPLE}}` など）に置きます。ベース名は `S<章>_<節>_<内容>` の形にして、本の節番号がそのまま読めるようにします（例 `{{BASENAME_EXAMPLE}}`）。辞書順が節順になります。新しい演習ファイルを作ったら `{{LIB}}.lean` に `import` を1行追加します。

日本語の解説資料（`.html`）も節ごとに置きます。原文を日本語で捉え直すための読む補助で、Lean の話はしません。作り方は `/exposition` にあります。解説と演習は兄弟で、どちらも出典はテキストです。解説を先に書きます。

## 証明コードを書かない原則

ユーザーが明示的に依頼しない限り、Lean の証明コードを書かないでください。ユーザーの学習過程を置き換えるために、証明を先回りして完成させないでください。

自然言語での説明はしてよい対応です。数学的な概念、証明方針、Mathlib のどこを探すか、形式化の方針。

Lean のコードには触れないでください。`by ...` 以降を完成させる、`sorry` を埋める、書きかけの証明ブロックを直す、頼まれていない `theorem` を足す。明示的に依頼されたときだけ、その宣言に限定して編集します。statement とヘッダは、許可なく変更しないでください。

## 環境

toolchain と Mathlib の rev は `lean-toolchain` と `lakefile.toml` にあります。定義名は、ここに固定された Mathlib の版で確かめてから使ってください。

## 説明の言語

説明は日本語で行い、`Lean`、`Mathlib`、`lake build`、定義名、定理名、tactic 名などは英語のまま使ってください。
