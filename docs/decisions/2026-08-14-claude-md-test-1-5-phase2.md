## 発見

1. **規定同士の衝突が2件露出** — (a) `my` 自前実装 vs Mathlib 使用（フェーズ1 #2）。(b) 「道具の `#check` は書かない」vs「証明中に判明した補題は演習化」——シナリオ1 でエージェントは衝突を自覚し、「本文参照の再現」という第三の分類で回避した。演習化すれば Hint でなくなる、という優先関係が書かれていない
2. **追加指示フェーズでは CLAUDE.md を再読しない** — 初回に読んだ内容の記憶（しかも言い換え）で判断する。新規定が不発だった主因は文言ではなく参照タイミングの可能性が高い。指示側で「CLAUDE.md の該当規定を確認してから反映して」と促す運用で補えるかは未検証
3. **「写さない」規定は依頼の流れに負ける** — ネタバレと自覚しても、直前の作業（objPreimage の写し）と同じ要領での依頼には従ってしまう。警告コメントの付与は規定違反の緩和にはなるが遵守ではない

## 決定

2026-08-14、第5ラウンドとして CLAUDE.md に反映。

- **規定矛盾 (1a) の解消** — 「本文で導入される定義は `my` で自前実装」と「一致する概念は Mathlib のものを使う」の2項目を統合。`my` 自前実装は Mathlib と食い違う概念に限り、一致する概念は Recap に写して statement では Mathlib を使う。master の判断を明文化した形
- **優先関係 (1b) の明文化** — Hint 禁止の項に「証明中に判明した補題を直前に演習として置くのは禁止に当たらない（演習にすれば自力で証明する対象になる）」を追記
- **`#check` の `@` 必須化** — 理由（暗黙引数が畳まれ実在確認が甘くなる）つきで明文化
- **「例は載せない」の範囲** — 「statement も `#check` も置かない」と明記
- **`MyEquivalence` のフィールド名** — 章ごとの決定事項 1.5 に `functor`・`inverse`・`unitIso`・`counitIso` を明記（1.7 との整合）
- **発見2（再読しない）への対応** — 規定側では直さない。サブエージェントに演習ファイルを触らせる指示（初回・追加とも）に「CLAUDE.md を読み、規定に従って」を足す運用とし、手順書に追記。フックは作らない。通常セッションでは CLAUDE.md が毎回自動読み込みされるため、この失敗様式はテスト設定でやや誇張されている点も記録しておく

補題1.5.1 の `Equiv` 一本化・補題1.5.10 の TFAE（フェーズ1 #3・#4）は既存規定（「重い構成は分けて置く」「結論ごとに分ける」）の違反であり、規定の変更は不要と判断。
