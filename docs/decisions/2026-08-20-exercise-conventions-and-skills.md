## 1. 演習ファイルの形式を作り直した

差し戻しで繰り返し出た欠陥は3つの型に整理できた。

- **目次** — 「橋渡し補題は Part B と Part C に置いた」「全単射を3つ、自然性を2つに分ける」のように、すぐ下を見れば分かることの再掲
- **宙に浮いた記号** — コメント中の `X`・`H`・`α` が、そのコメント内でも直下の statement でも束縛されていない
- **作業報告** — 「〜に分ける」「〜を置いた」という、対象ではなく作業の説明

いずれも、コメントの散文が「同定・主張・形式化の判断」を同時に担っていたことから来ていた。演習が全部 `example`(無名)で、ファイル内の通し番号も振らない規約だったため、同定の手段がコメントしかなかった。

そこで情報の置き場所を固定した。**どの主張かは宣言の名前、形式化の判断はヘッダの表、主張とその論理構成はセクションの冒頭、Mathlib の対応物は `#check`。宣言のあいだに散文を置かない。**

- 演習に本の番号ベースの名前を付ける(`prop_2_2_3`・`thm_2_2_4_right_inv`・`cor_2_2_8_yoneda_full`・`ex_2_2_i_left_inv`)。`example` は使わない
- 大見出し(前提/本文の定義と主張/節末問題)は箱、セクション見出しは本の番号。箱の右端は閉じない(全角の字送りがフォント依存で揃わないため)
- セクション冒頭に主張1文と、複数宣言に割ったときだけ `構成:`(論理構成のみ、割った理由や証明方針は書かない)
- 1行なら `--`、複数行なら `/- -/`

### 2周目の欠陥の原因(4つ)

1. **3つの判定が同時に発火して割れる** — Recap の説明に「本文で導入される概念は原則置かない」「Mathlib と一致する本文の定義は例外として写す」「演習が再現する対象そのものは写さない」が優先順位なしで同居していた。節の中心概念はこの3つすべてに該当する
2. **「一致・食い違い」が操作的でない** — 何をもって一致とするかが書かれていなかった。圏論では「同じ概念が Mathlib にもある」がほぼ常に真なので、基準が無いと「一致」に倒れる。**曖昧さが常に演習を減らす向きに作用する**構造だった
3. **目的が規約に書かれていない** — 全部「Mathlib に対してどこに置くか」の言葉で書かれ、「ユーザーが自分で組む」という目的の文が無かったので、迷ったときに引き戻す力が無かった
4. **収録漏れを検出する手順が無い** — 検証は elaborate と `#check` の解決だけで、節の主題が丸ごと落ちても満点になる。1周目は言い換えが、2周目は定義2.1.4 が落ちたが、どちらも検証は通った

### 規約作りの教訓

規約は §2.2 の1ファイルだけを見て書き直した。2.2 には `my` の構造体定義が無い(Ψ は関数、充満忠実は Mathlib と一致)ため、「一致・食い違い」と「渡し方」の規則は一度も試されないまま通過し、それが2周目・3周目の欠陥になった。**規約を変えたら、性質の違う節で試す。**
