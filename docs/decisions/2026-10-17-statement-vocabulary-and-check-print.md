# 2026-10-17 statement の語彙を「Mathlib を参照、自前は対応物がないときだけ」に一本化し、`#check`/`#print` の使い分けを定めた(対象 3.4)

§3.4 の命題3.4.8 の余極限側が `[MyIsConnected J]` で書かれていた。根拠にした規約が、別の箇所の規約と矛盾していた。

## 症状

`/exercises` skill の 4 は、冒頭で「statement の語彙は Mathlib とデータの持ち方が同じかで決め、違えば自前の語彙で書く」と言い、末尾で「宣言が参照するのは原則 Mathlib、自前定義は対応物がない場合に限る」と言っていた。`MyIsConnected` は `IsConnected` と持ち方が違うので前者では自前、対応物があるので後者では Mathlib になり、両立しない。

`#check`/`#print` の規定も 2 の 2 項・3 項と 6 に分かれ、使い分けはどこにも書かれていなかった。

## 原因

持ち方の規則は 2026-08-20/21 の Recap 時代に「自前で組んで本体に置くか、Recap に写して Mathlib を使うか」を決めるために入れたもの。09-27 に Recap を廃止して「自前か Mathlib かは本にあるかで判定」に変えたとき、この規則が statement の語彙の規則として残った。

## 変更

規約を「読者が終えたときに持っていてほしいもの」から見直した。到達点は二つ: 節の定義と主張を自分で再現している、節の概念を以後 Mathlib の名前と形で使える。

- 前文をこの到達点で書いた
- 「ファイルの構成」(旧 6)を 1 に移した。2〜4 が「ヘッダの表に書く」と言う前にヘッダが何かを示すため
- 使い分け(現 3)の一文目を判定そのものにした: 「その節の本文が定義または記述しているものは自前で組み、それ以外は Mathlib のものを使う」。自前で組むものに Mathlib の対応物があれば一致を示す宣言を置き、以後の宣言は対応物を参照する、を第 1 項に書いた。`#check`/`#print` の規定もここに置き、到達点から書いた: 「読者が節の概念を以後 Mathlib の名前と形で使えるようにするために置く。…読者が Mathlib の定義をまだ知らないとき（組んだものと形が違う、または本にない）は `#print` にする」
- 旧 4「statement の語彙と橋渡し」を削除した
- 答えの伏せ方(現 5)を原則「読者が見つけるべきものは置かない」から書いた
- 収録の「番号の有無では判定しない」、書式の「右端を閉じない」「`/-- -/` は使わず」、完成の確認のリンタの扱いなど、過去の修正の形で残っていた文を削った。リンタの扱いは CLAUDE.md の環境の節に移した
- 「持ち方」「橋渡し」「包装」の語を規約から外した

§3.4 では `prop_3_4_8_colimits`・`ex_3_4_ii_ii` の `[MyIsConnected J]` を `[IsConnected J]` に直す。§3.1〜3.3 は遡及しない。
