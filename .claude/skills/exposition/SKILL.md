## これは何か

テキストの副読本です。その節の内容を日本語で過不足なく解説する独立した文書で、それだけ読んで節がわかるものにします。出典はテキスト（所在は CLAUDE.md にある）。原文を日本語で捉え直すための読む補助であり、翻訳ではありません。同じ節の演習 Lean は兄弟であって、こちらは Lean には一切触れません。

本文の該当節を通読してから書く。同じ節の演習ファイルより先に、これを書く（読者が節を把握してから演習に入れるように、そして書き手が本文を自分の言葉で書ける状態にしてから演習を設計するため）。書式（CSS・レイアウト・SVG の流儀）は直前の節の解説 HTML に倣う。

## 収録

節にあるもの全部を、本の順序で。動機・定義・主張（番号の有無を問わない）とその証明・例・数学的な内容のある脚注・図・節末問題。演習ファイルに載せるかどうかで取捨しない。節が章の冒頭にあるときは章の導入も含める。

## 書き方

- **翻訳ではなく、数学の解説を書く。** 節を理解したうえで、定義・主張・証明の中身を自分で説明し直す。原文の訳や語句の置き換えではない
- 証明も、本文にあるものは省かず解説する。本文が図で示す計算は、図を再現したうえで、どの要素をどう追うかを文章で補う
- 冒頭に記号表（記号・型・意味）を置く。Lean 側の対応物は書かない
- 新しい定義・定理は、直感を一言、次に登場する記号の説明、最後に形式的な記述、の順で出す
- 記号は初出時に導入する。定義していない概念を使わない
- 用語は原典または一般文献で通用しているものだけを使う。比喩や造語で概念を命名しない
- 執筆の経緯・編集方針・実況口調を書かない。文書は結果だけを載せる
- 節末問題は和訳・言い換えを載せる

### 書かないこと

- Lean・Mathlib への言及、演習ファイルの構成や読む順序の指示
- 節末問題の解答、証明のヒント、難易度の示唆（どの主張が自明か、実質的かなど）

### 形式

- 自己完結の単一 HTML（外部リソース・CDN 不使用）、ライト/ダーク両対応
- 可換図式は inline SVG。ASCII アートを使わない。矢尻は `marker`、文字色は `currentColor` でテーマに追従、`max-width: 100%` で横スクロールを出さない
- 数式は Unicode 記法。数式レンダリングライブラリを使わない

## 検証

- **収録漏れ** — 本文の節にある項目（定義・主張・例・Remark・図・数学的な脚注・節末問題）を列挙し、その一つ一つが HTML に現れることを確認する
- **形式** — 外部リソースへの参照が無いこと、ライト/ダークの両方で読めること、タグが閉じていること
