対象の節: $ARGUMENTS

解説資料は、読者がその節を読むための日本語の学習ノートである。読み終えたとき、読者はその節の定義・主張・証明・例を理解していて、演習ファイルに取りかかれる。以下の基準で迷ったときは、読者がこの状態になるほうを選ぶ。

着手の条件: 本文 PDF（https://emilyriehl.github.io/files/context.pdf）の該当節を通読する。同じ節の演習ファイルより先に書く。書式は `Riehl/Ch2_Yoneda/S2_2_Yoneda.html` に揃える。CSS・レイアウト・SVG の書き方も同じ。

## 1. 収録

節にあるもの全部を本の順序で並べる。節の動機、定義、主張（番号の有無を問わない）とその証明、例、Remark、数学的な内容のある脚注、節末問題。節が章の冒頭にあるときは章の導入も含める。

## 2. 書き方

節を理解したうえで、定義・主張・証明の内容を自分の言葉で説明する。本文を引用するときは和訳を主にする。番号（定義2.1.4 など）は本と揃える。

- 冒頭に記号表を置き、記号・型・意味を並べる
- 証明は本文にあるものをすべて解説する。本文が図で示す計算は、図を再現したうえで、どの要素をどう追うかを文章で補う
- 節末問題は問題文の和訳または言い換えだけを載せる

この文書は本文を読むためのもので、Lean と無関係である。Lean・Mathlib・演習ファイルには触れない。

## 3. 形式

- 自己完結の単一 HTML（外部リソース・CDN 不使用）、ライト/ダーク両対応
- 可換図式は inline SVG で描く。矢尻は `marker` で描き、文字色は `currentColor` を継承させてテーマに追従させる。`max-width: 100%` で横スクロールを出さない
- 数式は Unicode 記法で書き、数式レンダリングライブラリは使わない

## 4. 完成の確認

次の 2 点を確認し、通ってから完成と報告する。

- 収録漏れ — 本文の節にある項目（定義・主張・例・Remark・図・数学的な内容のある脚注・節末問題）を列挙し、その一つ一つが HTML に現れることを確認する
- 形式 — 外部リソースへの参照が無いこと、ライト/ダークの両方で読めること、タグが閉じていること
