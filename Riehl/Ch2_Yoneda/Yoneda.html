2. この節の物語

出発点は 2.1 の続きの問い（pp. 59–60）: 例2.1.5・2.1.6 の表現を理解するには、自然同型 α : C(c,−) ≅ F を定めるデータが何かを知りたい。まず一般化して、自然変換 α : C(c,−) ⇒ F を定めるデータを問う。冒頭の引用は、Mac Lane が Gare du Nord のカフェと発車前の列車で米田からこの補題を聞き出し、後に命名したという逸話（p. 59）。

本文はいきなり一般論に入らず、ウォームアップを2つ置く。例2.2.1（p. 60）は ω 添字の図式で、α : ω(k,−) ⇒ F が要素 α_k ∈ Fk の選択ひとつで完全に決まり、しかもどの選択も許されることを図で見る。例2.2.2（pp. 60–61）は BG 添字で、同じ現象が「同変写像 ϕ : G → X は ϕ(e) で決まる」という形で現れ、命題2.2.3（p. 61）にまとまる。どちらの場合も、決め手の要素は「表現対象の恒等射の像」である。

これが偶然でないというのが定理2.2.4（米田の補題、p. 61）: ev_id : Hom(C(c,−), F) → Fc は全単射で、しかも c と F の両方について自然。証明は2部構成で、全単射の証明（pp. 61–62）は逆写像 Ψ を構成する。核心は、α の自然性の四角形が Ψ(x)_d(f) の値を強制するので、定義の選択の余地がないこと。自然性の証明（pp. 62–63）は F 方向（縦合成の定義から即座）と c 方向（四角形 (2.2.6) を使う）の2つの主張に分かれる。

注意2.2.7（pp. 63–64）は補題の言い直し: C が small なら C(c,−) は評価関手 ev_c : Set^C → Set を表現し、二変数の自然性は C × Set^C 上の2関手の間の自然同型として一枚に畳める。系2.2.8（p. 64）が本節のもう一つの主役で、米田埋め込み よ が充満忠実であることを補題から導く。脚注10: 「よ」は Yoneda の頭文字のひらがな。例2.2.9（p. 65）は ob, mor : Cat ⇒ Set の間の自然変換が 1 → 2 の3つの関手で尽きることを見る。表現対象の間の射を数えれば自然変換が尽くせる、という系2.2.8 の使い方の練習として読む。

締めは埋め込みの充満性の圏論外への応用2つ: 系2.2.10（p. 65、行操作はある行列の左乗法）と系2.2.11（pp. 65–66、Cayley の定理）。3つ目のパラダイム的応用は命題2.3.10 に予告されている。

4. 形式化のズレの背景

  • Set と locally small — 集合の圏は Type v₁ で置き換える。「C が locally small」は「hom が Type v₁ に住む」という universe 設定そのもので、仮定としては現れない（注意1.7.3・LocallySmall の対応と同じ）。
  • 定理2.2.4 のパッケージング — 本は「ev_id が全単射で、両変数について自然」。Mathlib は全単射を一本の Equiv（coyonedaEquiv）に、自然性を別補題（coyonedaEquiv_naturality・coyonedaEquiv_comp）に分けて持つ。演習ではさらに Equiv を「構成 Ψ + 往復2本」にほどいた。一つの Equiv にまとめると、解く側が同じ分解を作り直すことになるため。
  • Ψ を丸ごと sorry にした理由 — 1.7 の my 定義は「data を書いて proof obligation だけ sorry」だったが、ここでは data も書かない。Ψ(x)_d(f) の式を自分で見つけること（自然性が定義を強制すること）が本節の証明の核心だから。
  • 自然性の非対称 — F 方向の自然性は縦合成の定義からほぼ即座（本文も1行）。c 方向が四角形 (2.2.6) を使う実質的な方。演習の2本にはこの軽重の差がそのまま残る。
  • 注意2.2.7 — 二変数の自然同型への畳み込みは Mathlib では coyonedaLemma : coyonedaPairing C ≅ coyonedaEvaluation C（SET への持ち上げは uliftFunctor で処理される）。Remark なので演習にはしない。
  • 命題2.2.3 — BG 上の関手 = G-set の辞書（例1.3.9・1.4.4）は Mathlib では MulAction、同変写像は MulActionHom（G →[G] X）に化ける。全単射は本文どおり写像 ϕ ↦ ϕ(e) を固定して Function.Bijective で述べる。Mathlib の対応物は X = G の場合の MulActionHom.End.equivMulOpposite（モノイド一般、右乗法を Gᵐᵒᵖ として述べる）だけで、一般の G-set 版はない。
  • 系2.2.8 — 充満・忠実は 1.5 で Recap 済みの Mathlib クラス Functor.Full・Functor.Faithful で述べ、結論ごと（共変・反変 × 充満・忠実）に4宣言に分ける。Mathlib ではインスタンスとして登録済みなので、inferInstance で閉じれば演習にならない点は自力の約束に委ねる。
  • 演習2.2.i — 「State and prove」の State の部分は、ファイルに statement を置いた時点で消えている。双対の statement を自分で立てたい場合は、ファイルを見る前に紙で立ててから照合する。
  • 演習2.2.iii — ω は ℕ を Preorder.smallCategory で圏と見たもの（hom は ULift (PLift (k ≤ n))、Recap に写しあり）。「ωᵒᵖ 添字の族として記述する」前段と「米田の補題に訴えず直接」という制約は Lean では表現できないので、後者は自力の約束とする。
  • 系2.2.10 — Mat_R の圏は Mathlib にないため、「Hom(−,n) の自然自己変換」を「Matrix (Fin n) (Fin m) R 上の写像の族 + 右乗法との可換性（自然性）」に言い換えた。行操作という語は statement には現れない。対象を正整数でなく ℕ（0 を含む）にしたズレもある。
  • 系2.2.11 — 「置換群の部分群と同型」は ∃ H : Subgroup (Equiv.Perm G), Nonempty (G ≃* H) に。Mathlib の対応物は Equiv.Perm.subgroupOfMulAction（忠実な作用一般への一般化）。
  • 載せなかった節末問題 — 2.2.ii（説明問題）、2.2.iv（Cat の対象 I・2 を持ち回る構成が重い）、2.2.v・2.2.vii（「記述せよ・特徴づけよ」型で、statement を置くと答えの一部を書くことになる）、2.2.vi（Top と Path 関手の設営が重い）。いずれも問題文をコメントで残した。
